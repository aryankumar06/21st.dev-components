## 2024-05-24 - Accessibility and Tooltips on Icon-Only Buttons
**Learning:** Icon-only buttons must explicitly declare both `aria-label` (for screen readers) and `title` (for visual tooltips). In Shadcn/Lucide setups, icons don't inherently communicate their action to either assistive technologies or sighted users needing clarification. Missing these attributes is a common accessibility trap in dense UIs like habit trackers.
**Action:** Always add both `aria-label` and `title` attributes to icon-only buttons as a standard procedure to ensure an inclusive and intuitive user experience.
## 2024-05-24 - File Upload Keyboard Accessibility
**Learning:** When hiding a native `<input type="file">` element (using `display: none`) and wrapping it with a styled `<label>` element for visual presentation, the file input becomes inaccessible to keyboard navigation because screen readers and keyboard focus ignore hidden elements. The `<label>` itself does not naturally receive focus or trigger a click on 'Enter' / 'Space' via keyboard.
**Action:** Always make the wrapping `<label>` keyboard focusable by adding `tabIndex={0}`, provide an `onKeyDown` handler that triggers a click on the internal file input when 'Enter' or 'Space' is pressed (ensuring event bubbling is handled with `e.target !== e.currentTarget` if there are child interactive elements like a 'remove' button), and add visible focus styles (e.g., using `onFocus` and `onBlur` or `focus-visible` pseudo-class) so keyboard users know when the custom upload area is focused.
