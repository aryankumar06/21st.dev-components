## 2024-05-24 - Accessibility and Tooltips on Icon-Only Buttons
**Learning:** Icon-only buttons must explicitly declare both `aria-label` (for screen readers) and `title` (for visual tooltips). In Shadcn/Lucide setups, icons don't inherently communicate their action to either assistive technologies or sighted users needing clarification. Missing these attributes is a common accessibility trap in dense UIs like habit trackers.
**Action:** Always add both `aria-label` and `title` attributes to icon-only buttons as a standard procedure to ensure an inclusive and intuitive user experience.
## 2024-05-24 - Accessible Hidden File Inputs
**Learning:** When hiding a native `<input type="file">`, the wrapper element (e.g. `<label>`) needs to be explicitly made accessible via `tabIndex={0}` and styled on `onFocus`/`onBlur`. Furthermore, to allow keyboard activation (Enter/Space), an `onKeyDown` handler must manually trigger the `click()` event on the nested input. When adding this handler, it's critical to stop nested interactive elements (like a "Remove" button) from bubbling and accidentally triggering the file input open dialogue, by verifying `e.target === e.currentTarget`.
**Action:** When creating custom styled file inputs, ensure keyboard navigation and focus visibility are restored using manual handlers on the wrapper, and explicitly handle event bubbling for any child interactive elements.
