## 2024-05-24 - Accessibility and Tooltips on Icon-Only Buttons
**Learning:** Icon-only buttons must explicitly declare both `aria-label` (for screen readers) and `title` (for visual tooltips). In Shadcn/Lucide setups, icons don't inherently communicate their action to either assistive technologies or sighted users needing clarification. Missing these attributes is a common accessibility trap in dense UIs like habit trackers.
**Action:** Always add both `aria-label` and `title` attributes to icon-only buttons as a standard procedure to ensure an inclusive and intuitive user experience.
## 2025-02-28 - Hidden File Input Label Dropzones
**Learning:** When hiding a `<input type="file">` (e.g., using `display: none`) and relying on its wrapping `<label>` to act as a dropzone/trigger, the component becomes inaccessible via keyboard navigation. Users cannot tab to it or press Enter to trigger the file dialog. Furthermore, if inner interactive elements (like a "Remove file" button) exist, pressing Enter on them will bubble up and accidentally re-trigger the upload dialog.
**Action:** When creating label-wrapped file inputs, always ensure the `<label>` receives `tabIndex={0}`, visible focus state management (like `outline`), and an explicit `onKeyDown` handler that triggers `e.currentTarget.click()` on Space/Enter. Always include `if (e.target !== e.currentTarget) return;` to prevent child interaction events from bubbling.
